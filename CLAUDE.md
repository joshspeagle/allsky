# CLAUDE.md

allsky is an animated all-sky map of the Milky Way's stars. It shows the mean tangential velocity as moving streams, and the stellar density, metallicity and age as colour overlays, in nine distance bins from 0 to 50 kpc. The data come from brutus fits to PanSTARRS1, 2MASS, UKIDSS, unWISE and Gaia photometry. allsky is a fork of [cambecc/earth](https://github.com/cambecc/earth), an animated wind map.

## Layout

- `public/`: the whole site. It is static, and a copy of it is the deployed site.
- `public/index.html`: the page and its menu.
- `public/js/`: the application code, as ES modules. `main.js` is the entry point: the page wiring, the interpolated field, the particle animation and the overlay. `configuration.js` holds the settings and their URL hash; `agent.js` runs the asynchronous tasks; `events.js` is the event emitter both build on; `globes.js` holds the map projections; `products.js` the data layers, their colour scales and the grid interpolation; `util.js` the helpers.
- `public/libs/`: the vendored libraries, d3 and d3-geo-projection, which `index.html` loads as classic scripts before `main.js`. The modules read them as `window.d3`.
- `public/data/<bin>/<quantity>.json`: the data, one file per distance bin (`0-2kpc` to `20-50kpc`) and quantity (`velocity`, `density`, `metallicity`, `age`), on a 1 degree grid in Galactic longitude and latitude. Each file is a JSON array of records `{header, data}`: one record for a scalar, two for `velocity` (the components u and v, in km/s). Unobserved cells are `null`.
- `public/styles/`: the stylesheet and its subset font.
- `dev-server.js`: a local static server (Express) for `public/`.
- `tests/`: the Playwright regression tests and their snapshots (`tests/snapshots/`).

### URL hash

The hash holds the view as segments separated by `/`, in any order: a distance bin (`7-11kpc`), an overlay (`velocity`, `density`, `metallicity`, `age` or `none`), a projection with an optional orientation (`orthographic=λ,φ,scale`), and `grid` for the grid points. A missing or unknown segment takes its default, `7-11kpc/velocity/mollweide`. `configuration.js` parses and writes it.

## Commands

- Set up: `npm ci`. Node 20.19 or later.
- Run: `node dev-server.js 8080`, then open http://localhost:8080.
- Lint: `npm run lint` (ESLint, configured in `eslint.config.js`). It checks the Node scripts, `tests/` and the application code in `public/js/`.
- Test: `npm test`. It runs the unit tests of the pure functions in `tests/unit/` (Node's test runner), then the Playwright regression tests in `tests/` against the dev server, in Chromium. Without the preinstalled browsers, run `npx playwright install chromium` once.
- Update the test snapshots: `npx playwright test --update-snapshots`, only for an output change the lead approved. Check every changed file in `tests/snapshots/` before committing it.
- CI (`.github/workflows/ci.yml`) runs the lint and the tests for every push to `master` and every pull request.
- Dependabot opens monthly pull requests for npm packages and GitHub Actions. It skips `@playwright/test`: update it by hand together with the CI image, then run the tests and check any changed snapshot.

## Deployment

- The site is https://joshspeagle.com/allsky/, served by GitHub Pages. The `deploy` job in `ci.yml` publishes `public/` after the tests pass on a push to `master`, so a merge changes the live site.
- Pages serves files as they are stored: no server logic. The site lives under `/allsky/`, so every path the page loads must be relative.
- A pull request that changes what the site loads says so under Deployment.

### Minor changes

- A minor change has at most 10 changed lines and is not part of a larger edit. It fixes a typo, a link or formatting, rewords text outside `CLAUDE.md` without changing its meaning, or records in `CLAUDE.md` a decision the lead gave, adding nothing the lead did not say.
- It edits only prose. It changes no behaviour, number, colour, dependency, test or CI workflow. When unsure, it is not minor.
- Claude commits a minor change on top of `origin/master` and pushes it with `git push origin HEAD:master`. If the push is rejected, Claude rebases onto `origin/master` once and retries; if that fails, Claude opens a pull request instead.

## Code

- Write the minimum code that is correct, clear and fast. Prefer removing to adding; deleting a concept beats adding a flag.
- Write no code when the change is not needed, or when the platform or a library already in use does it.
- No no-ops, dead code, commented-out code, or new linter-ignore rules.
- One purpose per function, one group of things per file. Add a helper only when it is reused or a function is too long.
- Names are readable words. Symbols for coordinates may follow the math: `λ` and `φ` for Galactic longitude and latitude in degrees, `u` and `v` for the velocity components.
- Vendored libraries are not edited. Update one by replacing it with the published file of a named version, in a directory named after the version, with its licence.
- The site needs no build step: `public/` is what the browser loads. Every path in it is relative, so the site works from any directory of a static host.

## Numerics and rendering

- Coordinates are Galactic longitude `ℓ` and latitude `b` in degrees. Grids follow the earth layout: `lo1`, `la1` is the first grid point, longitude increases eastward from it and latitude decreases from it (scan mode 0).
- The field is interpolated bilinearly on the grid, then corrected for the projection's local distortion with finite differences (`distortion` in `util.js`).
- Stream speed on screen is deliberately non-linear in the velocity, so that the wide range of velocities stays visible.
- Randomness (particle seeding) uses `Math.random`. Tests that compare pixels compare only deterministic layers, or seed it.

## Tests

- Hermetic: no network, no files outside the repository.
- Write a test only when it catches a plausible bug in this code that no other test catches.
- Test contracts, invariants and regressions (each bug fix adds a test that fails without it). Do not test a library's behaviour.
- Assert on values and pixels, never on wall-clock time.
- The pixel snapshots come from Chromium on Linux, as in the CI image `mcr.microsoft.com/playwright:v1.56.1-noble`. On another platform, run the tests in that image.
- The tests wait on `data-field-overlays` on the `<html>` element, which `main.js` increments after it draws the overlay of a new field. A rewrite keeps this signal.
- Name a test as a sentence that states the behaviour: `masked cells show no overlay colour`.

### Text on GitHub

Issues, pull requests, comments, commit messages and phase reports have readers who are new to the code. This text follows the templates in `.github/` and these rules, adapted from ASD-STE100 Simplified Technical English:

- Lead with a summary, then the background a new reader needs.
- Short sentences: at most 20 words for an instruction and 25 for a description. One idea per sentence, at most six sentences per paragraph.
- Active voice, simple tenses, and full sentences with articles.
- One word for one meaning, and the same term for the same thing everywhere. Define each term and abbreviation where it first appears.
- A condition comes before the instruction it controls. Numbered lists for steps, tables for comparisons, headings so a reader can find each part.
